    트러블슈팅¶

    요약 실서비스 배포에서 겪은 문제 6가지. 프롬프트 비대화(응답 6.8초에서 1.5초로), 로컬에서는 잡을 수 없는 토큰 만료 버그(403과 401), 예외를 중복으로 오역한 거짓 메시지, 무료 API의 간헐 혼잡, 예고 없이 바뀌는 외부 API 응답, 조용히 실패하는 CSS 마이그레이션.

    실서비스 배포 과정에서 실제로 겪은 문제들입니다. 각 사례는 현상, 원인 분석, 해결, 결과 순서로 기록했습니다.

    사례 1. 프롬프트 비대화로 채팅 응답 6.8초¶

    인스트럭션 14,043자를 3,666자로 줄여 응답 6.8~9.0초를 1.5~2.0초로 (펼쳐 보기)

    현상: 대화 품질 개선 작업(리듬 규칙, Big5 연동, 친밀도 반영)을 거듭할수록 응답이 느려져 6.8~9.0초에 달했습니다. 특정 이모티콘(ㅠㅠ)을 과도하게 반복하는 품질 문제도 같이 나타났습니다.

    원인 분석: 응답 시간을 3회 실측하고 서버 로그에서 시스템 인스트럭션 길이를 확인하니 14,043자였습니다. 기능을 더할 때마다 프롬프트 파일에 규칙과 예시가 누적된 것이 원인이었습니다. 예시 문장의 대부분이 "ㅠㅠ"로 끝나서 모델이 그 패턴을 따라 한 것도 같은 뿌리였습니다.

    해결: 프롬프트 3개 파일을 "규칙은 전부 보존, 중복과 예시만 제거" 원칙으로 재작성했습니다 (26.2KB에서 7.0KB로). 동적 컨텍스트와 중복되던 시간대별 톤 가이드를 삭제하고, 예시 10개를 핵심 1~2개로 줄였습니다. 동시에 이모티콘 사용 규칙(연속 턴 금지, 3턴에 1회 수준)을 명시했습니다.

    결과: 인스트럭션 14,043자가 3,666자로, 응답 6.8~9.0초가 1.5~2.0초로 줄었습니다. 같은 시나리오 5턴 테스트에서 ㅠㅠ는 0회(기존에는 거의 매 턴), 대화 리듬 규칙은 전부 유지됨을 확인했습니다.

    사례 2. 토큰 만료 후 자동 재발급이 되지 않던 문제¶

    403과 401의 불일치를 바로잡아 토큰 만료 시 자동 재발급이 동작 (펼쳐 보기)

    현상: 배포 다음 날부터 "미안해, 지금 답변을 할 수 없어"(채팅 실패)와 설정 로드 실패가 발생했습니다. 서버 로그에는 Expired JWT token이 초당 수 회 반복됐습니다.

    원인 분석: 액세스 토큰(24h) 만료 자체는 정상입니다. 문제는 프론트의 "401 수신 시 refresh 토큰으로 재발급" 인터셉터가 한 번도 발동하지 않은 것이었습니다. 백엔드를 확인하니 Spring Security에 authenticationEntryPoint가 없어 미인증 요청이 기본값인 403으로 떨어지고 있었습니다. 프론트는 401만 기다리고 백엔드는 403만 주니 재발급 루프가 영원히 시작되지 않았습니다.

    해결: Security 설정에 커스텀 EntryPoint를 추가해 미인증과 만료를 401과 JSON 에러 바디로 통일했습니다. 403은 인증은 됐지만 권한이 없는 경우(소유권 위반)에만 쓰도록 시맨틱을 분리했습니다.

    결과: 만료 시 첫 401에서 자동 재발급 후 원 요청을 재시도합니다. 사용자는 아무것도 느끼지 못합니다. 리프레시(7일)까지 만료되면 로그인 화면으로 자연스럽게 유도됩니다.

    사례 3. 컬럼 길이 초과가 중복 일기로 표시된 문제¶

    컬럼 길이 초과를 중복으로 오역하던 예외 처리를 분리하고 컬럼을 1500자로 확장 (펼쳐 보기)

    현상: 배포 환경에서 일기 생성 시 "오늘의 일기는 이미 만들어졌어요"가 떴지만, 실제로 일기는 존재하지 않았습니다.

    원인 분석: 서버 로그를 추적하니 일기와 그림 생성은 전부 성공했고, 마지막 저장에서 SQL Error 22001: value too long for varchar(500)이 났습니다. 두 가지가 겹친 복합 버그였습니다.

    1. 무료 배포 환경에서 삽화를 Pollinations URL로 저장하도록 바꿨는데, URL에 그림 프롬프트 전체가 인코딩되어 들어가 500자 제한을 초과했습니다. 로컬에서는 짧은 파일 경로라 재현되지 않았습니다.
    2. 저장 코드가 DataIntegrityViolationException을 전부 중복 일기로 번역했습니다. 길이 초과가 "이미 존재함"으로 둔갑했습니다.

    해결: image 컬럼을 500자에서 1500자로 확장했습니다 (엔티티, init-db.sql, 운영 DB ALTER 동시 반영). 예외 번역도 고쳤습니다. 무결성 위반 시 실제로 일기가 존재하는지 재조회해서 중복일 때만 중복 응답을 주고, 아니면 원 예외를 로깅한 뒤 전파합니다.

    결과: 같은 생성 경로에서 길이 초과 저장 실패가 사라졌고, "이미 만들어졌어요" 메시지는 실제 중복일 때만 나옵니다. 로컬에서 재현되지 않는 배포 환경 차이(저장 경로 길이)를 로그로 추적해 잡은 사례입니다.

    사례 4. 무료 이미지 API의 간헐적 실패¶

    재시도 4회, 삽화 재생성 API, 복구 UX의 세 겹으로 대응 (펼쳐 보기)

    현상: Pollinations(무료 공용 인프라)가 혼잡 시간대에 500과 402를 간헐적으로 반환했습니다. 그림 없는 일기가 생겼고, 당시 UX에는 재시도 수단이 없었습니다. 감정 선택은 하루 1회라 생성 버튼도 다시 누를 수 없었습니다.

    원인 분석: 무료 공용 인프라의 혼잡이라 서비스 쪽에서 제어할 수 없는 외부 요인이었습니다. 문제는 실패 자체가 아니라, 실패하면 사용자가 아무것도 할 수 없는 구조였습니다.

    해결: 세 겹으로 대응했습니다.

    1. 재시도 강화: 지수 백오프 재시도를 1회에서 4회로 (혼잡은 보통 수초 내 해소됩니다)
    2. 복구 API: POST /api/diary/{id}/image. 일기 본문은 유지하고 삽화만 재생성합니다
    3. 복구 UX: 그림 없는 일기 상세에 "다시 그려달라고 하기" 버튼, 감정 선택 후 실패 시 안내 모달 재진입 경로

    결과: 일시적 혼잡은 재시도 안에서 흡수되고, 그래도 실패하면 일기 본문은 보존된 채 사용자가 삽화만 다시 요청할 수 있습니다. 외부 장애가 일기 저장을 막지 않는다는 원칙이 UX까지 이어졌습니다.

    사례 5. 카카오 로그인 응답에서 kakao_account 누락¶

    null-safe 파싱과 폴백 체인으로 카카오 응답 변경에 대응, redirect_uri 잠복 버그도 수정 (펼쳐 보기)

    현상: 카카오 로그인에서 토큰 교환까지 성공했는데 최종 단계에서 500이 났습니다. 로그: Cannot invoke "Map.get" because "kakaoAccount" is null.

    원인 분석: 2025년 말 카카오 개발자 콘솔 개편 이후 신규 앱은 동의항목 설정 구조가 바뀌어, 동의항목이 없는 앱의 /v2/user/me 응답에 kakao_account 블록 자체가 빠질 수 있습니다. 기존 코드는 이 블록의 존재를 전제로 체이닝 접근하고 있었습니다.

    해결: null-safe 파싱과 폴백 체인을 넣었습니다. 닉네임은 kakao_account.profile, properties, 기본값("집사") 순으로 찾고, 이메일이 없으면 카카오 ID 기반의 결정적 대체 이메일(kakao_{id}@catus.local)로 유니크 제약을 충족합니다. 닉네임은 어차피 온보딩에서 직접 입력받으므로 UX 손실은 없습니다.

    추가로 잡은 것: 토큰 교환의 redirect_uri가 설정 파일의 미해석 템플릿 문자열({baseUrl}/...)로 전송되던 잠복 버그. 인가 요청과 토큰 교환의 redirect_uri는 문자열까지 일치해야 합니다(KOE303). 환경변수로 외부화해 프론트 주소와 단일 소스로 맞췄습니다.

    사례 6. Tailwind v4 마이그레이션 후 레이아웃 깨짐¶

    Tailwind v4 진입 구문 교체로 preflight 복구, 좌우 여백 39/39px 대칭을 수치로 검증 (펼쳐 보기)

    현상: 모바일에서 채팅 입력 바가 오른쪽으로 16px 돌출했습니다. 수치로는 좌측 여백 39px, 우측 7px로 비대칭이었습니다.

    원인 분석: Tailwind v4는 진입 구문이 @import "tailwindcss"로 바뀌었는데, 구버전 문법(@tailwind base)을 쓰면 에러 없이 조용히 무시됩니다. preflight(box-sizing: border-box 리셋)가 전역에서 빠지면서 width: 100% + padding이 content-box 기준으로 계산돼 넘친 것입니다. 같은 뿌리에서 h1 거대화, 겹침 등 증상이 연쇄됐습니다.

    해결: 진입 구문을 교체하고 Vite 템플릿의 잔여 CSS를 제거했습니다.

    결과: 뷰포트 390x844 헤드리스 스크린샷으로 좌우 여백 39/39px 대칭을 수치로 검증했습니다. 이후 레이아웃 변경은 같은 스크립트로 확인합니다.
